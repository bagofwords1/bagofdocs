The **Google Cloud Storage** connector points BOW at a bucket, optionally scoped to a prefix. The agent lists objects, greps them, and reads them — including inside PDF, Word, PowerPoint, Excel, CSV and email files — and can attach an object to a report. Objects too large to load whole can be read in byte-range windows.

<Note>
  This connector is in **beta**. Fields and behavior may change between releases.
</Note>

It is a **file** connection, listed under **Files & object store** in the add-connection picker: the agent sees files and reads them, it does not write SQL against them. The connection is read-only.

## How it works

BOW builds a file catalog from the bucket. It uses the same parsing and search pipeline as [Amazon S3](/data-sources/connectors/s3) and [Files and Directories](/data-sources/connectors/files-and-directories):

- **`list_files`** — a bounded object listing under the prefix.
- **`read_file`** — a full object download, with `.csv`/`.tsv`/`.xlsx`/`.xls` parsed into tables and `.pdf`/`.docx`/`.pptx` text-extracted.
- **Windowed reads** — a ranged download for objects too large to load whole (logs, ndjson, big CSVs).
- **`grep_files`** — line-level grep with an explicit file, byte and time budget, and a resumable cursor.

There is no live full-content search: a content scan over an object store is one download per object, so keyword search runs against the indexed catalog instead. Writes are not supported, and BOW requests a read-only Cloud Storage scope.

Everything is confined to `bucket` + `prefix`. A file id is the object name **relative to the prefix**, and any id that escapes it is rejected.

## Before you start

- The bucket exists and you know its name (without the `gs://` prefix).
- The identity you will use can list and read objects in the bucket — for example, the **Storage Object Viewer** role on the bucket.
- For **Service Account Key**, you have the service account's JSON key file.
- For **Application Default Credentials**, the backend host must already carry a Google identity — GKE workload identity, a VM's service account, or `GOOGLE_APPLICATION_CREDENTIALS`.

## Connect in BOW

Go to **Data Sources → Add data source → Google Cloud Storage** and fill in the form.

| Field | Required | Default | Notes |
| :-- | :-- | :-- | :-- |
| `bucket` | Yes | — | Bucket name, e.g. `acme-reports`, without the `gs://` prefix. |
| `prefix` | No | — | Folder-like prefix that scopes the connection, e.g. `reports/2025/`. All listing and reads are confined to it. Blank means the whole bucket. |
| `project` | No | — | Google Cloud project that owns the bucket. When blank, BOW uses the service account's project (or the default project of Application Default Credentials). |
| `endpoint_url` | No | — | Custom Cloud Storage API endpoint, for a private endpoint or an emulator. Leave blank for Google Cloud. |
| `include_globs` | No | — | Comma-separated glob patterns relative to the prefix, e.g. `docs/**/*.pdf`, `**/*.csv`, `reports/**`. When set, only matching objects are visible **and** readable. `**` crosses sub-folders, `*` matches one segment. |
| `recursive` | No | `true` | Enumerate objects below the prefix when listing and indexing. |
| `max_file_mb` | No | `100` | Reject whole-object reads above this size. Windowed byte-range reads are exempt. |
| `index_mode` | No | `content` | How much is cached from the bucket — see below. |
| `max_catalog_objects` | No | `5000` | Cap on objects indexed into the catalog, so a huge bucket cannot produce an unbounded catalog. |

### Indexing modes

Reads are always live; `index_mode` (**Indexing** in the form) only decides what is cached ahead of time.

| Mode | Label in BOW | What is cached | Use when |
| :-- | :-- | :-- | :-- |
| `none` | None (live only) | Nothing — listing and reads go live. | The bucket is huge or highly volatile. |
| `metadata` | Object list | The object list only. | You want a fast catalog without content search. |
| `content` | Contents (searchable) | The object list plus extracted keywords, so the agent can find objects by topic. | The default. |

An object whose size and modified time are unchanged since the last run is not downloaded again for keywords.

<Note>
  The **Full text** mode offered on [Amazon S3](/data-sources/connectors/s3#indexing-modes) and [Files and Directories](/data-sources/connectors/files-and-directories#indexing-modes) is not offered in the Google Cloud Storage form.
</Note>

## Authentication modes

Both modes are **system-scope only** — one shared credential serves every user of the connection. There is no per-user sign-in for Cloud Storage; restrict who can use the connection with access rules instead. See [Authentication and access](/data-sources/authentication).

### Service Account Key (`service_account`)

The default.

| Field | Required | Notes |
| :-- | :-- | :-- |
| `service_account_json` | Yes | The full JSON key file of a service account with read access to the bucket (e.g. the **Storage Object Viewer** role). |

### Application Default Credentials (`adc`)

No fields. BOW uses the Google credentials already present on the backend host — GKE workload identity, a VM's service account, or `GOOGLE_APPLICATION_CREDENTIALS`. Use this when the deployment already has a Google identity and you do not want to store a key in the product.

With this mode and a custom `endpoint_url`, BOW connects **anonymously** instead — for emulators and public buckets.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Service account JSON is not valid JSON">
    Paste the whole key file, including the outer braces, exactly as downloaded from Google Cloud.
  </Accordion>

  <Accordion title="No objects appear even though the bucket is not empty">
    Check `include_globs` — patterns are matched relative to `prefix`, so a pattern that repeats the prefix will never match. Also confirm `recursive` is on if the objects sit below sub-folders.
  </Accordion>

  <Accordion title="Access denied on read but listing works">
    The identity can list the bucket but not read those objects, or the object is outside `include_globs` — an off-glob object is denied, not just hidden.
  </Accordion>

  <Accordion title="A large object cannot be read">
    Whole-object reads above `max_file_mb` are rejected. Ask the agent for a windowed read, or raise the limit.
  </Accordion>

  <Accordion title="Only part of a large bucket is catalogued">
    The bucket exceeded `max_catalog_objects`. Narrow the connection with `prefix` or `include_globs` rather than raising the cap.
  </Accordion>
</AccordionGroup>
